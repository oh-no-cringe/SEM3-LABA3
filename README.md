# Лабораторная работа № 3 · структуры данных

Классы структур данных на C++17 и Go, консольное меню, файловое хранение, тесты и измерения покрытия.

Проект собирается и запускается следующими командами.

```sh
make
./build/lr3
```

Также можно выполнить `make run`. Для очистки результатов сборки есть `make clean`.

После запуска выбирается структура:

| Номер в меню | Структура | Файлы |
|---|---|---|
| 1 | Массив | `src/array/array.h`, `array.cpp` |
| 2 | Односвязный список | `src/forward_list/forward_list.h`, `forward_list.cpp` |
| 3 | Двусвязный список | `src/list/list.h`, `list.cpp` |
| 4 | Очередь | `src/queue/queue.h`, `queue.tpp` |
| 5 | Стек | `src/stack/stack.h`, `stack.cpp` |
| 6 | Хеш-таблица | `src/hash/hash_table.h`, `hash_table.cpp` |
| 7 | Полное двоичное дерево | `src/tree/tree.h`, `tree.cpp` |

`src/main.cpp` запускает меню и обрабатывает ошибки. Классы структур находятся в отдельных папках src. Консольное меню и обработчики находятся в src/cli. В main.cpp запускается меню и обрабатываются ошибки. В cli/menu.cpp выбирается структура, а в array.cpp, forward_list.cpp, list.cpp, queue.cpp, stack.cpp, hash.cpp и tree.cpp выполняются её команды. Общие функции ввода находятся в cli/input.cpp.

В массиве хранятся строки. Очередь поддерживает разные типы, поэтому её же реализация используется для указателей на узлы дерева. Дерево соответствует варианту ЛР1 — Complete Binary Tree. Хеш-таблица использует наш массив и поддерживает линейное пробирование и двойное хеширование.

После выбора структуры программа показывает доступные команды. Например, работа с массивом:

```text
1
PUSH apple
PUSH pear
INSERT 1 banana
GET 1
SET 0 orange
DEL 2
PRINT
EXIT
```

Значения с пробелами заключаются в двойные кавычки. Индексы начинаются с нуля. Команда `EXIT` завершает программу. Между запусками данные сохраняются командами `SAVE text путь` и `SAVE binary путь`; загрузка — `LOAD text путь` и `LOAD binary путь`.

| Структура | Команды |
|---|---|
| Массив | `PUSH`, `INSERT`, `GET`, `SET`, `DEL`, `SIZE`, `EMPTY`, `PRINT`, `EXIT` |
| Списки | `PUSH`, `FRONT`, `INSERT`, `DEL`, `DEL_VALUE`, `FIND`, `POP_FRONT`, `POP_BACK`, `EMPTY`, `PRINT`, `EXIT` |
| Очередь и стек | `PUSH`, `POP`, `EMPTY`, `PRINT`, `EXIT` |
| Хеш-таблица | `SET ключ значение`, `GET ключ`, `HAS ключ`, `DEL ключ`, `PRINT`, `EXIT` |
| Дерево | `INSERT число`, `FIND число`, `CHECK`, `PRE`, `IN`, `POST`, `EMPTY`, `PRINT`, `EXIT` |

Для хеш-таблицы после номера 6 вводится метод: 1 — линейное пробирование, 2 — двойное хеширование.

```text
6
2
SET apple red
GET apple
DEL apple
HAS apple
EXIT
```

В скрытой папке `.vscode` находятся настройки C++17 для редактора. Файл `.clang-format` задаёт оформление кода, `.gitignore` исключает результаты сборки из Git.

В tests находятся тесты GoogleTest: отдельный файл для каждой структуры. Запуск — make test. Для запуска одной группы можно использовать ./build/unit_tests '--gtest_filter=StackTest.*'. В тестах используются TEST, EXPECT_EQ, EXPECT_TRUE, EXPECT_FALSE и EXPECT_THROW. Библиотека GoogleTest 1.16.0 находится в third_party/googletest вместе с лицензией.

Те же 30 проверок написаны отдельно на Boost.Test в `tests/boost`: по одному файлу на каждую структуру. Файл `main.cpp` подключает готовый запуск тестов. Для сборки и запуска:

```sh
make test-boost
```

Для запуска только тестов стека:

```sh
./build/boost_tests --run_test=StackTest
```

В этих тестах `BOOST_AUTO_TEST_CASE` объявляет проверку, `BOOST_CHECK_EQUAL` сравнивает значения, `BOOST_CHECK` проверяет условие, а `BOOST_CHECK_THROW` проверяет исключение. `BOOST_REQUIRE` останавливает текущий тест, если условие нарушено. Библиотека Boost 1.87.0 находится в `third_party/boost` вместе с лицензией. Используется [вариант Boost.Test с реализацией в заголовочных файлах](https://www.boost.org/latest/libs/test/doc/html/boost_test/usage_variants.html). Устанавливать Boost в систему не требуется.

GoogleTest запускается отдельно командой `make test`. Эти два набора проверяют одни и те же структуры через две разные библиотеки тестирования.

Третья библиотека C++ — Catch2; 30 проверок находятся в `tests/catch`, библиотека с лицензией — в `third_party/catch2`. Запуск: `make test-catch`. Код сторонних библиотек разбирать не требуется.

Команды `make test` и `make test-boost` запускают библиотеки напрямую и выводят их штатные результаты.

Go-версия находится в `go`. Она использует структуры из наших ЛР1 и ЛР2, адаптированные к интерфейсу ЛР3: закрытые поля структур и открытые методы. Очередь — обобщённый тип `Queue[T]`, дерево использует эту очередь. Для начальной позиции хеш-таблицы Go использует FNV-1a, C++ — `std::hash`; порядок печати нескольких ключей может различаться, смысл операций одинаковый. В Go память освобождает сборщик мусора; содержащие указатели структуры не следует копировать по значению.

Сборка и запуск Go из корня `lr3`:

```sh
make go
./build/lr3-go
```

Либо `make run-go`. Номера меню и команды совпадают с C++.

Go-тесты находятся рядом со структурами в `go/structures/*_test.go`, тесты меню — в `go/cli/menu_test.go`, запуска — в `go/cmd/lr3/main_test.go`. Используются стандартный пакет `testing` и проверки `testify/require`. Готовые зависимости с лицензиями сохранены в `go/vendor`, их внутренний код разбирать не нужно. Для запуска тестов сеть не требуется.

```sh
make test-go
make lint-go
```

`lint-go` проверяет оформление через gofmt и выполняет go vet. Временные кеши Go находятся внутри `build`, основной системный кеш не изменяется.

HTML-отчёты о покрытии кода:

```sh
make coverage-cpp
make coverage-go
make coverage
open reports/index.html
```

`make coverage` заново запускает обе проверки и обновляет общую стартовую страницу. Для C++ нужны Clang, llvm-cov и llvm-profdata (на macOS вызываются через xcrun); для Go — Go 1.22 или новее. Для скриптов нужны bash и jq. Отчёты:

- `reports/index.html` — общая страница с процентами и ссылками.
- `reports/cpp/index.html` — LLVM HTML со строками и ветвями C++.
- `reports/go/index.html` — стандартный HTML go tool cover.
- `reports/cpp/summary.txt` и `reports/go/summary.txt` — текстовые сводки.

В C++ объединяется покрытие запусков GoogleTest, Boost.Test, Catch2 и контрольных консольных сценариев из `tools/coverage_cpp.sh`. Включены все собственные файлы `src`, в том числе меню и main. У Go учитываются пакеты `structures`, `cli` и `cmd/lr3`; незапущенные строки main остаются видны в отчёте. Тестовые файлы и сторонние библиотеки в расчёт не входят.

На текущем запуске C++ покрыл 94,13% исполняемых строк и 87,88% ветвей, Go — 96,60% исполняемых операторов. Метрики языков различаются. Команды проверки завершаются ошибкой, если тесты не проходят или итоговое покрытие строк C++ / операторов Go ниже 85%. Это покрытие кода, а не доля успешно пройденных тестов. В README значения зафиксированы для текущего запуска; HTML и сводки обновляются при повторной генерации.

Документация инструментов: [LLVM coverage](https://llvm.org/docs/CommandGuide/llvm-cov.html), [Go coverage](https://go.dev/doc/build-cover).


Файловая сериализация реализована для всех семи структур на обоих языках. C++: `src/storage/storage.h` и `storage.cpp`; Go: `go/structures/storage.go`. Файлы имеют общий формат и читаются другой языковой версией. Длина строк задаётся в байтах, поэтому сохраняются пустые строки, пробелы и переводы строк. В бинарном формате числа uint32 записываются little-endian. Сохраняются логические значения, порядок элементов и режим пробирования таблицы, но не адреса узлов или метки удаления. Дерево восстанавливается по обходу в ширину; поддерживается полная форма.

Проверка всех структур, направлений обмена и форматов создаёт 28 файлов в `data/serialization`:

```sh
make test-serialization
ls -lh data/serialization
cat data/serialization/cpp-array.txt
xxd data/serialization/cpp-array.bin | head
```

Команды можно вводить в меню обеих программ:

```text
1
PUSH apple
PUSH pear
SAVE text build/array.txt
SAVE binary build/array.bin
LOAD text build/array.txt
PRINT
EXIT
```

В списках используется единый идентификатор формата `list`: содержимое можно загрузить и в односвязную, и в двусвязную реализацию. Другие виды структуры имеют разные идентификаторы. Неверная сигнатура, другой вид структуры, неполная строка или лишние данные дают ошибку. Ограничения файла: 100000 строковых полей, до 1048576 байт в поле. Для таблицы дополнительно записывается поле режима и по два поля на пару.

Проверки оформления и все тестовые библиотеки:

```sh
make lint-cpp lint-go
make test test-boost test-catch test-go
make coverage
```

Benchmark:

```sh
make benchmark
cat reports/benchmark/cpp.txt
cat reports/benchmark/go.txt
```

C++ измеряет среднее время десяти созданий и заполнений структуры из 1000 элементов с оптимизацией -O2; Go использует стандартные Benchmark и benchmem. `ns/op` Go относится к одному пакету из 1000 добавлений. C++ включает уничтожение объекта, а освобождение памяти Go зависит от сборщика мусора. Эти результаты не являются строгим сравнением языков. Замеры не входят в расчёт покрытия исходников основного приложения.

Python-скрипты удалены. Автоматизация выполняется shell-скриптами; для извлечения сводки LLVM используется jq. Тестовые библиотеки выводят собственные итоги.

Статический анализ C++ выполняется командой `make lint-cpp`: сначала проверка форматирования clang-format, затем Cppcheck для собственных файлов src и benchmarks (C++17). Включены проверки ошибок, предупреждений, производительности и переносимости. Найденные замечания завершают команду с ошибкой. Результат сохраняется в `reports/lint/cppcheck.txt`. На macOS установка анализатора: `brew install cppcheck`. Сторонние библиотеки не анализируются.
